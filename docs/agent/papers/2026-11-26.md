## 1. One Ocean, Many Tasks: A Data-Grounded Simulation Suite and Benchmark for Marine Robotics / 一个海洋，多项任务：基于数据的模拟套件和海洋机器人基准

**Date**: 2026-11-25 | **arXiv**: [2611.34925v1](http://arxiv.org/abs/2611.34925v1) | **PDF**: [Link](http://arxiv.org/pdf/2611.34925v1)

**Categories**: cs.RO, cs.DB

<details><summary><b>Abstract / 摘要</b></summary>

Simulation is essential for marine robotics, yet existing platforms often trade off between visually realistic worlds, high-throughput experimentation, and ocean-condition realism grounded in real data. We present OneOcean, a data-grounded simulation suite and benchmark built around a unified spatiotemporal ocean-environment product that harmonizes bathymetry with data-driven currents and tides, with optional pollution fields for cleanup-related evaluation. On top of this environment representation, OneOcean defines a task ladder spanning navigation and station-keeping under currents, waypoint and route following, depth-profile tracking, area scanning, pipeline inspection, and multi-agent coordination, including formation transit, fish protection and patrol (herding), and surface pollution localization, containment, and cleanup. The suite supports multi-agent settings with 2-10 vehicles. Our simulator supports three to six Degrees of Freedom (DoF) and produces standardized metrics and reproducible run manifests, enabling consistent aggregation across tasks, difficulties, and scaling settings. Experiments across dataset variants and scenes systematically stress planning and control under data-grounded disturbances and reveal trade-offs among heuristic baselines, Behavior Cloning (BC), and a Large Language Model (LLM)-based planner.

模拟对于海洋机器人至关重要，但现有平台往往要在视觉上逼真的世界、高通量实验以及基于真实数据的海洋条件真实性之间做出权衡。我们推出了OneOcean，这是一个基于数据的模拟套件和基准，建立在一个统一的时空海洋环境产品之上，该产品将测深与数据驱动的海流和潮汐相协调，并提供可选的污染场，用于与清理相关的评估。在此环境表示的基础上，OneOcean 定义了一个任务阶梯，涵盖在洋流作用下的导航和定点保持、航点和航线跟踪、深度剖面跟踪、区域扫描、管道巡查以及多智能体协调，包括编队航行、鱼群保护和巡逻（驱赶）、以及水面污染定位、控制和清理。该套件支持包含2-10辆无人艇的多智能体设置。我们的模拟器支持三至六个自由度（DoF），并生成标准化指标和可重现的运行清单，从而能够在不同的任务、难度和扩展设置之间实现一致的聚合。跨数据集变体和场景的实验系统性地强调了在基于数据的扰动下的规划和控制，并揭示了启发式基线、行为克隆（BC）和基于大型语言模型（LLM）的规划器之间的权衡。

## 2. Shape-Aware Three-Way Merge for RDF Knowledge Graphs: The schema defines the conflict: an implementation and evaluation / 针对 RDF 知识图谱的形状感知三向合并：模式定义冲突：实现与评估

**Date**: 2026-11-25 | **arXiv**: [2611.34870v1](http://arxiv.org/abs/2611.34870v1) | **PDF**: [Link](http://arxiv.org/pdf/2611.34870v1)

**Categories**: cs.DB, cs.AI, cs.SE

<details><summary><b>Abstract / 摘要</b></summary>

Merging RDF serializations creates ordering conflicts and misses semantic ones. We describe and evaluate a three-way merge in which the schema defines a conflict: set algebra combines canonical triples, and a slot is contended only where a SHACL shape bounds its cardinality and both sides' changes cannot stand within that bound. Unbounded predicates union; contended slots go to a person. The same shapes graph validates the result. We do not claim the first three-way merge for RDF. Our contribution is an implementation in a production multi-agent store and an evaluation against a reimplementation of Quit Store's Context Merge overlap rule, which it extends rather than replaces, and six other strategies. Across five synthetic seeds, the shape-aware operator raised 33 conflicts, all true positives as judged by the same shapes that define them, with no triples lost or fabricated and no SHACL violations admitted. The context-overlap baseline, counted per slot, detected the same 33 conflicts but asked 845 questions. A replay built from recorded production incidents covers 105 human alias repairs (93 after excluding 12 chained pairs) and 939 duplicate-value incidents. It reproduces a triple-level limit: different names for one entity remain invisible (0 of 93 alias repairs detected, matching 0 of 21 synthetic cases). In a study of evolving shape contracts, merging shape declarations first handles the tested cardinality changes, while datatype evolution exposes a detector blind spot caught by post-merge validation. An oracle that reads no shapes agrees with the shipped operator on the facts and history of all 23 reachable single-slot cases. Under wrong shapes, a missing bound loses data silently and a spurious one only adds questions. The supported claim is fewer human decisions with nothing silently lost, for cardinality conflicts in one deployment, not general merge correctness.

合并 RDF 序列化会产生排序冲突，并错过语义冲突。我们描述并评估了一种三向合并，其中模式定义了一个冲突：集合代数将规范三元组组合在一起，并且只有在 SHACL 形元限制其基数且双方的更改都无法在该限制范围内时，才会发生槽冲突。无界谓词并集；冲突的槽位归属于一个人。相同的形状图对结果进行验证。我们并不宣称这是首个针对 RDF 的三向合并。我们的贡献是在生产多代理存储中的一种实现，以及对 Quit Store 的上下文合并重叠规则（我们的实现是对该规则的扩展而非替代）的重新实现和另外六种策略的评估。在五个合成种子中，形状感知运算符提出了 33 个冲突，根据定义这些冲突的相同形状的判断，所有冲突均为真阳性，没有三元组丢失或被伪造，也没有出现 SHACL 违规。按槽位计数的上下文重叠基线检测到了同样的 33 个冲突，但提出了 845 个问题。根据记录的生产事件构建的重现涵盖了 105 次人工别名修复（排除 12 对连锁对后为 93 次）和 939 起重复值事件。它重现了三元组级别的限制：同一实体的不同名称仍然不可见（在 93 个别名修复中检测到 0 个，与 21 个合成案例中的 0 个相匹配）。在一项关于演进型形状合约的研究中，合并形状声明首先处理经过测试的基数变化，而数据类型演进则暴露了检测器的盲点。

## 3. Deep Reinforcement Learning for Multi-UAV Data Harvesting Under Variable Team Sizes and Agent Loss / 针对不同团队规模和代理损失情况下的多架无人机数据采集的深度强化学习

<details><summary><b>Abstract / 摘要</b></summary>

Collecting data from wireless sensors can be challenging when limited communication infrastructure prevents them from offloading their measurements. <details><summary><b>Abstract / 摘要</b></summary>

<details><summary><b>Abstract / 摘要</b></summary>

Drafters that read the target's cache avoid one of their own, but settle only which cache, not which positions, and still read everything or a recent window. ## 8. VisualMontage: Manipulating the Beliefs of Vision-Language Agents with Authentic Image Sequences / VisualMontage：通过真实图像序列操纵视觉-语言代理的信念

**Date**: 2026-11-25 | **arXiv**: [2611.34603v1](http://arxiv.org/abs/2611.34603v1) | **PDF**: [Link](http://arxiv.org/pdf/2611.34603v1)

<details><summary><b>Abstract / 摘要</b></summary>

AI models vary enormously in capability and price. Model routing exploits this by sending easier tasks to cheaper models. We introduce partial routing, which guides a frontier lead model to delegate suitable subtasks to a cheaper worker model. These results show that analysis of past runs can support more efficient planning and more effective delegation, with little cost and implementation overhead.
