## 1. Beyond Prompt Injection: The Tool Update Gap in LLM Agent Security / Beyond Prompt Injection ： LLM专员安全性中的工具更新差距

**Date**: 2026-11-01 | **arXiv**: [2611.01976v1](http://arxiv.org/abs/2611.01976v1) | **PDF**: [Link](http://arxiv.org/pdf/2611.01976v1)

**Categories**: cs.CR, cs.AI

<details><summary><b>Abstract / 摘要</b></summary>

Large language model based agents increasingly rely on external tools to invoke services and interact with web resources. These tools can evolve through software updates, yet agentic frameworks may continue trusting them without re-verifying their safety after implementation changes. This tool update gap creates a supply-chain vulnerability in agentic systems: because updated tool code executes outside the LLM's context window, malicious functionality embedded in tool updates can bypass defenses centered on model-visible interactions, leaving agents exposed to stealthy, persistent threats that existing in-context defenses can hardly address.   To thoroughly investigate this threat, we introduce ETUDE (Exploiting Tool Updates for Direct Execution), an attack that embeds malicious functionality into updates of initially benign tools to produce compromised tools, while preserving their legitimate tool functionality. Unlike prompt-based attacks, ETUDE operates entirely outside the LLM's context and requires no adversarial instructions, thereby bypassing defenses restricted to model-visible content. We evaluate ETUDE across three representative attack workloads and seven widely used commercial and open-source agentic frameworks, including Gemini CLI, Codex CLI, and Claude Code. The results show that ETUDE achieves a 97.6% ASR while maintaining a 95.9% legitimate task completion rate.   We further examine existing defenses and find that they provide insufficient protection against this threat. These findings expose a fundamental blind spot in current agent security practices: trust established for a tool does not necessarily remain valid after its implementation updates.

基于大型语言模型的代理越来越依赖外部工具来调用服务并与Web资源交互。 这些工具可以通过软件更新不断发展，但代理框架可以继续信任它们，而无需在实施更改后重新验证其安全性。 这种工具更新漏洞在代理系统中造成了供应链漏洞：由于更新的工具代码在LLM的上下文窗口之外执行，因此工具更新中嵌入的恶意功能可以绕过以模型可见交互为中心的防御，从而使代理暴露于隐身、持续的威胁，而现有的上下文防御几乎无法解决。   为了彻底调查这种威胁，我们引入了ETUDE （利用工具更新直接执行） ，这是一种攻击，将恶意功能嵌入到最初无害的工具的更新中，以生成受损的工具，同时保留其合法的工具功能。 与基于提示的攻击不同， ETUDE完全在LLM的上下文之外运行，不需要对抗性指令，从而绕过仅限于模型可见内容的防御。 我们评估了三个具有代表性的攻击工作负载和七个广泛使用的商业和开源代理框架，包括Gemini CLI、Codex CLI和Claude Code。 结果表明， ETUDE实现了97.6%的ASR ，同时保持了95.9%的合法任务完成率。   我们进一步研究了现有的防御措施，发现它们没有提供足够的保护，

## 2. Launder-Bench: Can Repository-Level Agentic Code Laundering Be Detected? / Launder-Bench ：是否可以检测到存储库级别的代理代码洗钱？

**Date**: 2026-11-01 | **arXiv**: [2611.01966v1](http://arxiv.org/abs/2611.01966v1) | **PDF**: [Link](http://arxiv.org/pdf/2611.01966v1)

**Categories**: cs.SE, cs.AI

<details><summary><b>Abstract / 摘要</b></summary>

Coding agents can now rewrite repository-scale codebases while preserving tested behavior, creating a new challenge for plagiarism detection, license auditing, and software provenance. We ask whether such rewrites can still be traced to their source. Existing clone benchmarks emphasize fragments and bounded edits, while repository-transformation benchmarks evaluate functional correctness rather than provenance. Moreover, ranking the most similar source does not establish derivation when independent implementations can be similarly close. We define repository-level agentic code laundering and introduce Launder-Bench, to our knowledge the first repository-level benchmark for provenance under agentic rewriting, constructed from 282 real-world repositories. A source-hidden reconstruction protocol decomposes source behavior, reconstructs modules and repository structure, and retains rewrites only after execution-based verification. We evaluate the same provenance problem in two complementary settings: Launder-Bench-Pair contains 1,128 pairwise instances asking whether two repositories share provenance, while Launder-Bench-Attr contains 229 source-attribution instances asking which candidate is the source, with abstention when evidence is insufficient. Measured same-domain independent repositories establish how much similarity can arise without shared provenance and provide detector-specific reference bands. Existing methods remain far from saturating Launder-Bench: the strongest static method reaches only 0.66 AUROC on pairwise detection, while repository encoders rank the true source first on up to 22% of attribution queries but earn calibrated attribution credit on only 1-2%. These results reveal a systematic gap between relative code similarity and source-specific provenance evidence, providing a reproducible target for provenance detection under agentic rewriting.

Inspired by Popper's Three Worlds, we introduce TriPhysBench, a benchmark of 410 questions from 200 videos that brings physical perception, physical knowledge retrieval, and physical reasoning into a shared evaluation setting. ## 6. LegoEnv: Self-Evolving Agentic Environments via Modular Recombination / LegoEnv ：通过模块化重组实现自我进化的代理环境

**Categories**: cs.CL, cs.AI

<details><summary><b>Abstract / 摘要</b></summary>

LLM agents learn by interacting with environments, yet existing environments are designed for specific tasks and fail to generalize to new ones. Recent methods automate environment construction with LLMs. However, they generate each environment from scratch, neither reusing parts shared across environments nor carrying a fix from one environment to the rest. To address this, we propose a new paradigm of evolving environment atoms, which composes environments from reusable atoms (intent, rule, data and server) and evolves the atoms when an environment fails to give reliable feedback (e.g., an application lacks a tool the task requires). To instantiate this paradigm, we introduce LegoEnv, which builds 5,465 verified environments over 223 applications, and one round of evolution raises the share of solvable environments from 71.6% to 88.3%. On AutomationBench, SFT on these environments lifts Qwen3.6-27B from 16.0% to 32.0%, and RL with their verifiers lifts Qwen3.8-27B from 37.6% to 40.3%. Further analyses show steady gains with corpus size, transfer to unseen applications, and failures concentrated in a few shared root causes.

**Categories**: cs.MA, cs.AI, cs.CL

<details><summary><b>Abstract / 摘要</b></summary>

Large language model (LLM)-based multi-agent systems (MAS) tackle challenging tasks by dividing work among agents and coordinating their contributions toward shared objectives. Evaluating these systems therefore requires benchmarks that assess not only task-solving performance but also the ability to handle interdependent work. However, existing benchmarks often emphasize task difficulty without substantial collaboration requirements or evaluate only a limited range of predefined collaboration patterns. In this paper, we introduce MAC-Bench, a comprehensive benchmark for evaluating multi-agent collaboration through interconnected tasks. Rather than imposing predefined agent roles or communication protocols, MAC-Bench embeds collaboration requirements directly into task dependencies and shared-resource constraints. Specifically, we mine reusable collaboration structures from selected benchmark tasks at two levels. Local collaboration patterns capture recurring interactions among subtasks, while global task structures characterize how these interactions contribute to complete workflows. Through coarse-to-fine composition, these structures are recombined into task graphs combining different collaboration requirements. Tasks are instantiated in executable environments with automated verification of partial progress and complete task resolution.

**Categories**: cs.AI

<details><summary><b>Abstract / 摘要</b></summary>

Task success, retrieval quality, and cost do not show whether an LLM agent used a delivered memory or what followed from that use. We introduce MemUse, which evaluates memory at its point of use in recorded trajectories: each memory delivery is compared with what the agent could already see and followed through the agent's later actions and their consequences. An agentic judge rates each delivered entry's relevance, accuracy, novelty, influence, and observed effect; programmatic checks enforce complete reading of cited evidence, and fixed rules aggregate the ratings into verdicts linked to memory histories and delivery cost. On 8,000 SWE-bench Verified episodes from three memory systems, resolve rates stay within 0.4 percentage points of a no-memory baseline, yet MemUse shows that most delivered entries were irrelevant, most relevant entries went unused, and in two systems most deliveries restated content the agent could still see. ## 9. Principled Human-AI Collaboration in Agentic Workflows / Agentic工作流程中有原则的人工智能协作

**Date**: 2026-11-01 | **arXiv**: [2611.01566v1](http://arxiv.org/abs/2611.01566v1) | **PDF**: [Link](http://arxiv.org/pdf/2611.01566v1)

**Categories**: stat.ML, cs.AI, cs.LG, stat.ME

<details><summary><b>Abstract / 摘要</b></summary>

Organizations adopting AI face the challenge of deciding which outputs can be released without human review while meeting the quality standards of human experts. We develop a statistical framework for delegating tasks between experts and black-box generate-verify workflows, in which AI-generated answers are verified and revised over multiple rounds. Before deployment, human experts evaluate selected outputs, and their judgments are used to calibrate the verifier threshold and number of attempts. Our method selects the policy with the highest estimated automation rate among statistically approved candidates, without modifying the generator or verifier. We establish finite-sample control of the error rate among released outputs, characterize the expert evaluations sufficient to attain a target automation rate, and derive a minimax lower bound establishing rate optimality in the quality margin and required confidence. In a MultiHiertt financial question-answering case study, average held-out automation increases from 2.50% to 24.17% as expert evaluations accumulate, while released-output error rates remain around 1.20%.
